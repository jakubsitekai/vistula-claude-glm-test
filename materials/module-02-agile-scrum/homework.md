# Module 2 — Homework: More User Stories and a Real Agile Example

**Estimated time:** 30–60 minutes
**Individual work** (each student does this alone)

## Task 1 — Two more user stories with acceptance criteria (15–30 min)

1. Take the project you made with your partner in the lab.
2. On your own branch (`your-name/homework-2`), add **two more user stories** to the `## User stories` section in the README. They must be *different* from the ones you wrote in the lab.
3. Use the exact format:

   > As a *(kind of user)*, I want *(some goal)*, so that *(benefit)*.

4. Under each story, write **at least 3 acceptance criteria** as a checklist. An acceptance criterion is a condition that must be true for the story to count as "done" (see the Module 2 theory, section 3).
5. Commit with a clear message, push, and open a pull request. Your partner reviews it; after the review, merge it.

## Task 2 — A real-world example of Agile (15–30 min)

1. Find **one real example** of a team, company or product that works in an Agile way. Good starting points: Spotify, ING Bank, a mobile app you use that updates often, or any local company that uses Scrum. You can use the internet, but write the text in your own simple words.
2. Write a short text (about **5 sentences**) answering:
   - Who are they, and what do they build?
   - How do they work in iterations (for example: Sprints, frequent releases, regular updates)?
   - How does this *iteration* help them? (Think: fast feedback, quick fixes, changes in the plan are easy.)
3. Add this text to a new section in your README called `## Agile in the real world`. Include a link to the source you used.

## Task 3 — Push to the repository (5 min)

1. Merge your pull request into `main`.
2. Check that the README on github.com shows your two new stories and your Agile example.

## What to submit

Submit through the course platform on the assignment page (Assignments section): paste your GitHub repository URL / deployed app URL / PR URL as required.

- The **URL of your repository** (your partner's repo is fine, but your two user stories and your Agile text must be visible and must be yours).
- **Your name and student ID number.**

## Grading hints

- Correct user story format and real acceptance criteria = main part of the points.
- Your Agile example must be specific (name the team/product and a concrete way iteration helps them), not a general definition of Agile.
